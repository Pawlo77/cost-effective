The scoring function, decoded

Score = (TP × 10) − (FP × 5) − (NoVariables × 200)

This is not a standard ML metric — it is a profit function with three competing forces. Understanding the math before touching any data is the single most important step of this project.

Break-even analysis per variable

Cost of 1 feature
−200 pts
TPs needed to recover it
+20 TPs
Optimal threshold (math)
p > 0.333

The threshold derivation

For each customer you predict positive, their expected score contribution is:

E[score] = 10 × p(convert) − 5 × p(not convert) = 15p − 5

Setting this > 0 gives p > 1/3 ≈ 0.333. The default threshold of 0.5 is too conservative — you leave profitable TPs on the table. Tune aggressively downward, but never below 0.333 in expectation.

Key insight: The variable penalty (200 pts) dwarfs per-prediction gains. A feature that only marginally lifts TP rate is almost certainly net-negative. Target 5–15 features maximum.

Variable count targets

Conservative

5–10 variables

Cost: 1,000–2,000 pts. Low risk. Requires only 100–200 TPs on 1,000 predictions to break even on feature costs alone. Suitable if conversion rate in test set is unknown.

Aggressive

11–20 variables

Cost: 2,200–4,000 pts. Only justified if each marginal feature provably adds ≥20 TPs in cross-validation. Validate every feature addition with the custom CV scorer.

Hard rule: Never add a feature because it improves ROC-AUC or F1. Only add it if it improves your custom business score in held-out CV folds.

Trade-off summary

HURTS SCORE
False Positives (−5 each)
Extra Features (−200 each)
FP/FN in wrong predictions
vs
HELPS SCORE
True Positives (+10 each)
Fewer features used
High precision ≥ recall

FP penalty is half the TP reward, so precision matters but recall is still valuable. A model that is too conservative (very high precision, very low recall) sacrifices TPs unnecessarily. Balance: target precision ≥ 0.65 on your 1,000 predictions.

Feature selection strategy

With 500 anonymous variables and a 200-point penalty per feature, this is the highest-leverage part of your entire project. Use a three-stage funnel.

Stage 1 — Broad filter

Univariate + tree-based importance

Goal: Reduce 500 → ~50–80 candidates using fast, model-agnostic filters.

1
Mutual information filter
Use sklearn.feature_selection.mutual_info_classif to score all 500 features against the binary label. This captures non-linear dependencies. Eliminate the bottom 60–70% of features.
2
LightGBM / XGBoost feature importance
Train a quick tree model on all remaining features. Extract feature_importances_ (gain-based). Keep the top 50–80 by combined gain. This is fast and handles multicollinearity implicitly via tree structure.
3
Remove near-zero variance and duplicate columns
Check variance thresholding (VarianceThreshold) and correlation matrix — remove one of any pair with |corr| > 0.95. Free eliminations that cost nothing.
Stage 2 — Regularisation

L1 / LASSO selection

Goal: Reduce ~80 → 15–30 using penalty-based sparsity.

4
Logistic Regression with L1 penalty
Fit LogisticRegression(penalty='l1', solver='saga', C=tunable) across the Stage 1 survivors. L1 drives irrelevant coefficients to exactly zero. Try a range of C values (0.001 to 1.0) and select features that survive across multiple C levels — these are the most robust.
5
LightGBM with strong regularisation
Use reg_alpha (L1) and min_child_samples tuned high. Features with zero splits in 5-fold CV are eliminated. The union of L1-Logistic and LGBM selections gives your candidate pool.
Stage 3 — Business-score refinement

Custom-scorer RFECV + greedy search

Goal: Reduce ~30 → final 5–15, validated against the exact business metric.

6
RFECV with custom scorer
Run RFECV(estimator=lgbm, cv=5, scoring=custom_scorer) on your 30-feature pool. This iteratively removes the least important feature and measures the change in your actual business score, not AUC.
7
Forward greedy search (the deciding step)
Start from your top 5 features. Add one at a time: if the custom CV score improves by more than 200 pts (the cost of adding one feature), keep it. Otherwise discard. This directly optimises the scoring function. Stop when no candidate passes the 200-pt threshold.
8
Permutation importance validation
On your final model, run permutation_importance from sklearn. Any feature whose removal does not degrade the business score by at least 200 pts should be dropped from the final submission.
Critical: Run all feature selection inside your CV loop. Leaking feature selection information across folds inflates scores and produces a falsely optimistic variable set.

Recommended models

Primary

LightGBM

Best all-round for tabular imbalanced data. Fast training allows extensive Optuna hyperparameter search. Native support for scale_pos_weight and custom objectives. Use as your main candidate.

Ensemble partner

XGBoost

Strong alternative that often predicts differently enough from LGBM for blending. Use eval_metric='aucpr' during training and tune max_depth, subsample, colsample_bytree.

Baseline + sparse

Logistic Regression L1

Invaluable as an interpretable baseline and for the final report. Naturally produces sparse models. If it achieves competitive scores with ≤10 features, its simplicity could outperform complex models after the −200 penalty.

Handling class imbalance

In the model

Set scale_pos_weight = n_neg / n_pos in LGBM/XGBoost. This re-weights the loss function without altering the dataset.

In the data (optional)

SMOTE or ADASYN on training fold only (never on validation). Test whether oversampling actually improves your custom score — it often does not for tree models.

Threshold tuning — the profit curve method

Standard classifiers output probabilities. The question is: which probability cutoff maximises your score when selecting at most 1,000 clients?

1
Get out-of-fold probability predictions
Use cross_val_predict(method='predict_proba') on training data to get OOF probabilities for all 5,000 training clients. These are unbiased estimates of the model's confidence.
2
Sort descending by predicted probability
Rank all training clients from most to least likely to convert. This gives you a ranked list to work with regardless of threshold.
3
Compute the profit curve
For each candidate cutoff k = 1 to 1000, select the top-k clients, compute TPs and FPs against known labels, and calculate Score(k) = TP×10 − FP×5 − N_features×200. Plot Score(k) vs k.
4
Pick k* = argmax Score(k)
The peak of the profit curve gives you the optimal number of predictions. Often this is well below 1,000 — submitting fewer, higher-quality predictions beats submitting all 1,000.
Math check: The per-prediction break-even is p > 0.333 (derived earlier). For your test set, translate k* back to a probability threshold and apply it directly to test predictions.

Optuna hyperparameter search

Use Optuna with direction='maximize' and your custom scorer as the objective. Key LGBM parameters to search:

num_leaves: [20, 300]
learning_rate: [0.01, 0.3] (log-uniform)
n_estimators: [100, 2000] + early stopping
reg_alpha: [0.0, 2.0] ← L1, affects feature sparsity
min_child_samples: [10, 100]
subsample: [0.5, 1.0]

Run 100–200 trials with 5-fold CV. Total wall time with LGBM should be under 2 hours on a laptop.

Class distribution table. Histogram of feature variance. Missing value heatmap. Note: with 500 anonymous features, EDA focuses on statistical properties, not domain interpretation. 2 figures max.

Feature Selection Methodology
Describe the 3-stage funnel (mutual info → L1 regularisation → greedy search). Include a table: Stage | Features In | Features Out | CV Score. Plot: business score vs number of features used — this is your key analytical contribution.

Modelling & Threshold Optimisation
Model comparison table (Logistic, XGBoost, LGBM, Ensemble) with CV business scores. Profit curve plot (score vs k predictions). Report final threshold k* and the predicted vs expected TP/FP split. Optuna convergence plot optional.
§5 — 0.75 pg
Results, Discussion & Limitations
Final CV score and expected test score estimate. Sensitivity analysis: what if conversion rate in test differs by ±2%? Limitations: anonymous features limit interpretability. What would you do with more time/data?

One-paragraph summary of decisions made and trade-offs accepted. Restate the final model, feature count, and expected score.
